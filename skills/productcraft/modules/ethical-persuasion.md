# Behavioral and conversion UX without deception

Variable rewards, loss aversion, scarcity, reciprocity, fake loading, phantom typing, color pressure and hidden checkout fees are powerful and easy to misuse (patterns 6-9, 18, 28, 55 in `../references/pattern-library.md`). Knowing how they work is not an endorsement.

## Techniques to implement when real and relevant

- Make legitimate primary actions clear, use specific value propositions and concise benefit-oriented copy. Support real price/feature comparisons and an obvious opt-out.
- Real urgency can be shown when objectively true and continuously verified: genuine deadline, limited appointment capacity or actual stock. Explain why it is limited; never recycle countdown timers.
- Genuine social proof: authentic reviews, legitimate counts, transparent sample sizes, clear review provenance and consent. Do not fabricate stars, viewers, sales or clinic availability.
- Helpful defaults: preselect the path that is best for most users only when clearly editable and not more costly or invasive without meaningful consent. For sensitive choices, explicitly ask.
- Motivation: progress that measures real work, celebrated milestones, reminders that are easy to control, meaningful rewards tied to actual actions. Avoid compulsive randomized reward loops.
- Reduce friction: remove duplicate steps and fields, use autofill, permit easy cancellation/refunds as applicable, offer contextual support and strong error recovery.
- Reciprocity: create real value before asking for a commitment; don't imply a user owes the app something or generate false social pressure.

## Patterns to detect and remove

Fake scarcity/countdowns, phony human typing, fake spinners, hidden service fees, prechecked expensive extras, disguised sponsored content, confirm-shaming, subscription traps, misleading opt-out copy, coercive streaks, concealed app limitations and barriers to account deletion.

## Evaluation

Optimize for task completion, users' informed decisions, appropriate conversions, retention from delivered value, low support load, complaints/refunds and accessibility rather than clicks alone. Run experiments transparently and measure harm/complaints, not only funnel progression.

## Safety override

These instructions never authorize deception, fraud, financial exploitation, medical pressure, vulnerable-user manipulation, privacy violations or bypassing user consent. If a tactic relies on false claims or intentionally trapping users, document it as an anti-pattern and propose an honest alternative.
